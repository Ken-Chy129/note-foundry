# NoteFoundry v0.2 Learning Sources Plan

## Goal

Deliver the Learning Sources scope in `docs/product-scope.md` without turning captured material into Learning Notes or introducing v0.3 AI capabilities. A Learning Source is private input to learning; user-approved Markdown Learning Notes remain the primary knowledge output.

## Current sequencing decision

Development may begin before the production S3 acceptance gate for v0.1 is closed. This changes delivery order only: the encrypted offsite backup and real restore requirement remains part of v0.1 and must not be marked complete until exercised.

## Technical baseline

- Go modular monolith module: `backend/internal/sources/`.
- PostgreSQL remains the runtime system of record.
- REST contracts are described in `api/openapi.yaml` before exposure.
- Source management routes require the configured Knowledge Owner session.
- Web extraction and PDF parsing run as PostgreSQL-backed Jobs.
- Learning Sources, extracted content, Capture Notes, files, and management views are never public.

## Commands

- Backend tests: `cd backend && go test ./...`
- Backend static checks: `cd backend && go vet ./...`
- Frontend tests: `cd frontend && npm test`
- Frontend checks: `cd frontend && npm run lint && npm run typecheck`
- Frontend build: `cd frontend && npm run build`
- Local stack: `docker compose up -d --build`

## Source model

A Learning Source has a stable UUID and one of three kinds: `manual`, `url`, or `pdf`.

- `title`: owner-visible source title.
- `captureNote`: why the source was saved or what to examine.
- `content`: the current manual or extracted textual content; no revision history.
- `processingStatus`: `pending`, `processing`, `ready`, or `failed`.
- `spaceId`: nullable. A null value means the source is in the Source Inbox.
- `originalUrl` and `normalizedUrl`: URL-source metadata, added in the URL slice.
- PDF identity and managed bytes are added in the PDF slice through a source-owned storage record rather than weakening Note Attachment ownership rules.

The first slice creates only `manual` sources. They are immediately `ready`, require no Job, and default to the Source Inbox.

## API shape

First slice:

- `GET /api/v1/sources?inbox=true&page=1&pageSize=50` lists private Learning Source summaries, newest first.
- `POST /api/v1/sources` creates a manual Learning Source from `title`, optional `captureNote`, and optional `content`.
- `GET /api/v1/sources/{sourceId}` returns the complete private source.

Later slices add ordinary resource updates plus explicit command endpoints for organize and retry-extraction behavior. All errors use the existing structured API error format and all list endpoints remain paginated.

## Delivery slices

### Slice 1: Manual Source Inbox

Acceptance criteria:

- The owner can create a manual Learning Source without selecting a Knowledge Space.
- The source appears immediately in the Source Inbox with stable identity and `ready` status.
- Title, Capture Note, and content round-trip through PostgreSQL.
- Anonymous requests and requests without an owner session cannot list, create, or read sources.
- The workspace exposes a distinct Learning Sources / Source Inbox entry, separate from the note directory tree.
- Empty, loading, error, and populated inbox states are represented in Chinese.

### Slice 2: Organize sources

- Assign or move one source to a primary Knowledge Space.
- Show organized sources in a dedicated source view for that space, never in the note directory tree.
- Return a source to the Source Inbox by clearing its primary space.

### Slice 3: URL capture and deduplication

- Validate HTTP(S) URLs and store the original URL.
- Normalize scheme, host, default ports, fragments, and stable query behavior.
- Reuse an existing source for the same normalized URL.
- Enqueue durable extraction after the source record is committed.

### Slice 4: Web extraction Jobs

- Claim, retry, and record extraction failures through PostgreSQL-backed Jobs.
- Store one current extracted text representation without source revisions.
- Preserve the source and Capture Note when extraction fails.
- Provide an explicit retry command.

### Slice 5: PDF capture and parsing

- Validate PDF content and size at the upload boundary.
- Store bytes through managed source storage with an immutable key and checksum.
- Deduplicate by file hash and parse asynchronously through Jobs.
- Keep all source files private, including when referenced by public notes.

### Slice 6: Note-to-source references

- A Learning Note can reference multiple Learning Sources and vice versa.
- Owner views expose full source details; public note views expose only citation metadata and original URLs.
- Captured text, Capture Notes, and internal files never enter public responses or search projections.

## Checkpoints

After every slice:

- New domain behavior has tests that fail before implementation and pass afterward.
- Persistence behavior is covered by PostgreSQL integration tests.
- OpenAPI, Go responses, and TypeScript types agree.
- Backend and frontend full test suites pass and the production build succeeds.
- No v0.3 concepts, secrets, or public source-content routes are introduced.

## Risks and mitigations

| Risk | Mitigation |
| --- | --- |
| Captured content leaks through public APIs or search | Keep all source routes owner-only and introduce a separate citation DTO later. |
| URL extraction becomes a synchronous latency problem | Persist first, then enqueue a durable Job. |
| PDF ownership weakens Attachment visibility rules | Use explicit source-owned storage metadata rather than nullable polymorphic ownership. |
| Duplicate URLs or files create clutter | Normalize URLs and hash files before creating a second source. |
| Learning Sources become mistaken for approved notes | Keep separate navigation, vocabulary, tables, API types, and UI views. |

## Explicit exclusions

- AI summaries, embeddings, RAG, Agent execution, and automatic note creation.
- RSS, news feeds, browser automation, and scheduled collection.
- Public access to Learning Source content or files.
- Learning Topics and multi-user permissions.
